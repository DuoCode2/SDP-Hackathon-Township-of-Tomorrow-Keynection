# Jiran5 原型（项目名待定）

Sime Darby Property University Hackathon 2026 · People 赛道 · "邻里圈 + 信任账本"合并版的原型。

所有住户、门牌、姓名和示范照片都是虚构或程序画出来的，不是 SDP 的真实数据，也没有真实住户的照片。

## 四层都能演示了

设计语言是「活的蓝图」：整个 app 画成 SDP 自己的建筑图纸，有平面图、共用墙、图框和公文印章，因为邻里圈本来就是从平面图算出来的。

| 层 | 画面 | 做什么 |
|---|---|---|
| 1 认识 | Circle | 平面图上标出共用墙和楼板，装修中的房子与共用墙用橙色斜线警示；点任何一户看住户、关系和语言，可以直接发讯息；英文/马来文/中文自我介绍 |
| 1–2 沟通 | Chats | 跟圈子里每户一对一聊天；快捷回复自动翻成对方的语言；「提出不满」升级阶梯（邻居 → 装修户回复/处理 → SDP 物业团队），每步写进两户屋历；语气检查、检举、静默封锁；电话号码要双方同意才交换 |
| 2 约定 | Works | 装修日历（周日斜线标示禁止施工）与"现在是否安静时段"；地方政府（PBT）准证状态；承包商 QR 通行证；门卫扫码模拟；承包商只看得到自己那份工程资料；屋主随时撤销 |
| 3 证据 | Evidence → 案件 | 开工前照片（质量检查、指纹封存）；跟进照片自动对齐、"AI 扫描"动画、HUD 框标出裂缝或水渍；按公开规则给建议，人来决定 |
| 4 关闭 | Evidence → 保修、SDP | 判定为建筑瑕疵就自动开保修单；每张单显示《房屋发展法》附表 G/H 的时钟（交屋后 24 个月保修期、通知后 30 天内修好）；SDP 提交维修照片时，系统拿它跟开工前照片对比；**只有屋主能关闭**，驳回就重开 |
| 屋历 | Log | 每户一条 SHA-256 链：交屋、装修、通行证、照片、案件、决定、维修、屋主确认都在里面，每块都显示自己的指纹和上一块的指纹 |
| 后台 | SDP | 三个工作台：保修（30 天时钟、逾期标红）、物业（升级上来的不满：提醒或结案）、安全（被检举的讯息：私下警告或驳回）；邻居自行解决的比例等数据 |
| 信任 | Safeguards | 设计时想到的 11 类风险，每项列出原型已做（Built）和试点要做（Pilot）的措施，并能跳到对应功能 |

**演示工具**：顶栏的角色卡清楚写出每个人是谁（装修户、隔壁邻居、对面、楼上、楼下）；「Both sides」开分屏，左右两边同时看 Aiman 和 Siti，中间是一道「共用墙」；右上角「导览」有中英文功能说明和可以一键跳转的演示路线。

## 怎么运行

需要 Python 3.12 以上和 Node.js 20 以上。

### 最简单：双击一键启动

| 档案 | 用在 | 做什么 |
|---|---|---|
| `start-demo.bat` | Windows，演示、彩排 | 双击就好。第一次会自动装好全部套件（要几分钟），之后每次只需约 10 秒。自动打开 http://localhost:8000 ，前后端同一个窗口、同一个端口。演示时窗口不要关，关掉就停止 |
| `start-demo.sh` | macOS / Linux | 同上，在终端执行 `./start-demo.sh` |
| `start-dev.bat` | 改代码时 | 开两个窗口：后端（改 Python 自动重载）和前端（改画面即时更新），打开 http://localhost:5173 。要先跑过一次 `start-demo.bat` |

不想自动开浏览器：先设环境变量 `JIRAN_NO_BROWSER=1`。

### 手动启动（开发者用）

后端（第一次要先建虚拟环境）：

```bash
cd prototype/backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```

前端（另开一个终端）：

```bash
cd prototype/frontend
npm install
npm run dev
```

打开 http://localhost:5173 。电脑上是网页版：左边是导航，右边是「导览」面板（中文/英文切换，说明这一页的功能，并列出可以一键跳转的演示路线）；窗口窄于 1240 像素时导览改成按右上角按钮滑出；窄于 900 像素（手机）时改为全屏加底部导航。服务器默认只在本机开放，同一 Wi-Fi 里的其他人连不进来。

测试（68 个）：

```bash
cd prototype/backend
.venv/Scripts/python -m pytest -q
```

重新生成示范照片（一般不需要）：

```bash
cd prototype/backend
.venv/Scripts/python scripts/make_demo_photos.py
```

## 演示路线（约 7 分钟）

彩排前先到 SDP 页底部按 Reset demo data。右上角「导览」里有同样的路线，点一步就会自动跳过去。

1. **Circle**，Aiman（No. 12）：看平面图上的共用墙 → 勾"I'm planning renovation"（含 PBT 准证）→ 发送；No. 12 和它的共用墙变成橙色斜线
2. 按 **Both sides** 开分屏（左 Aiman、右 Siti）→ 两边都切到 **Chats**
3. Siti：Wave back → 按快捷回复"宝宝午睡"→ 左边 Aiman 看到英文翻译
4. Siti：**Raise a concern** → 晚上施工 → 发送；Aiman 回复；Siti 升级给 SDP 物业团队
5. 左边切到 **SDP → Estate**：提醒 Aiman 遵守屋规 → 结案（两边对话都看得到）
6. （可选）Siti 打一句辱骂的话，展示语气检查
7. Aiman：**Works → Contractor passes** → 发通行证 → 门卫扫码：周日 10:00 被拒、平日 10:00 放行
8. Siti：**Evidence** → Use sample → Sample crack → Building defect → Record decision
9. **SDP → Warranty**：看 30 天法定时钟 → Sample: poor patch → Siti 驳回 → Sample: proper repair → Siti Accept
10. **Log**：不满、升级、保修、维修、屋主确认全部在链上，显示 CHAIN VERIFIED
11. 最后打开 **Safeguards**：每个风险怎么处理，一页讲完

## 路演时要注意的创新点（根据证据调研）

- **第二层不是新东西**：CIDB 的"Hak Jiran"指南已要求通知邻居、限定施工时段；VYROX 等物业系统已有承包商时效通行证和非时段警报。第二层只当"配套"，不要当卖点。
- **真正的差异在**：邻居一侧的开工前存证、"装修造成 vs 建筑瑕疵"的分流、维修后拿开工前照片自动核对、只有屋主能关闭、按《房屋发展法》计时、整条屋历链，以及「先邻居、后物业」的不满升级阶梯。调研没找到马来西亚有产品同时做到这些。
- **法律依据要讲准**：附表 G（有地）和 H（分层）规定交屋后 24 个月保修期、收到书面通知后 30 天内修好；修不好屋主还可以找购屋者索偿仲裁庭（Tribunal for Homebuyer Claims）。路演前请队员再核对一次条文。
- 证据以有地房为主（21 宗对 5 宗分层），公寓"楼上装修导致楼下漏水"的公开案例很少，路演时不要夸大。

## 安全与稳定（已做的）

- **照片隐私**：上传照片一律重新编码，去掉 GPS、相机型号、拍摄时间（有测试验证）
- **上传检查**：只接受真正能解码的 JPEG/PNG/WebP；超过 12 MB 或像素过多直接拒绝；防"解压炸弹"
- **存储**：照片用随机 ID 命名，ID 格式不对一律 404，防止路径穿越；对比图网址带照片 ID，不会显示到别的案件的旧图
- **通行证**：QR 里是 32 位随机令牌，服务器只存它的 SHA-256 指纹，资料库外泄也做不出能用的通行证；令牌只在发出时显示一次；每项装修最多 3 张有效通行证；屋主可撤销
- **最少权限**：承包商视图不含屋主电话、邻居姓名、任何照片、其他住户；有测试逐项检查
- **权限检查**：只有装修户能发/撤通行证；只有收到通知的邻居能挂照片、提出不满；只能拿自己的照片报案；只有圈子里的 5 户能互相发讯息；只有收件人能检举；只有提出不满的人能升级；**SDP 只能提交维修，不能关闭保修单，只有屋主能**；状态机防止重复提交或重复决定
- **沟通安全**：语气检查挡掉明显辱骂；每位邻居每天最多 30 则；封锁是静默的（被封锁的人发的讯息会保留纪录但对方看不到）；检举者匿名，警告只有发送者看得到；电话号码双方同意才交换
- **输入限制**：讯息、装修内容、时段、备注都有长度和格式限制；结束日期和时段不能颠倒
- **CORS** 只允许本机前端；回应加上 nosniff、禁止嵌入等安全标头
- **演示专用功能**（重置、示范照片、模拟扫码时间）在设 `JIRAN_DEMO_MODE=0` 时自动关闭
- **不依赖外网**：字体、图标、QR 生成都打包在本地，演示现场断网也能跑
- **不卡**：照片对比约 0.2 秒；启动时预热 OpenCV；拖动滑杆、数字动画都不重新渲染整页；前端压缩后约 100 KB
- **版本锁定**：后端依赖版本全部固定；资料表结构变了会自动重建示范资料

## 还不是正式产品的地方（路演时要老实说）

- 没有登录：顶栏的角色卡和分屏只为演示；正式试点要用 WhatsApp 一次性密码之类的身份验证
- 快捷回复是预先翻译好的；自己打的字不会翻译（试点可以接翻译服务）
- 语气检查只是一份简单词表，试点需要更完整的多语言判断和人工审核
- 「24 小时后才能升级」在演示模式下关掉了，方便现场展示（`JIRAN_DEMO_MODE=0` 时生效）
- WhatsApp、CIDB 注册检查、Procore 编号、门卫扫码都是模拟的
- 演示时通行证令牌暂存在浏览器分页里（关分页就清掉）；正式版会通过 WhatsApp 链接只发给承包商
- 真实墙面通常很素，自动对齐需要画面里有墙角、插座、开关等固定物；对不齐时系统会请用户重拍，不会乱判
- 变化检测只找"变暗"的区域（裂缝、水渍、污痕），不判断原因

## Git

这个资料夹已经是本机 git 仓库（分支 `main`），还没有连到任何线上仓库。`.gitignore` 已排除虚拟环境、node_modules、打包结果和演示资料库，只会提交源代码和示范照片。

放上 GitHub 时：先在 GitHub 建一个 **Private** 仓库（不要勾"加 README"），然后：

```bash
git remote add origin https://github.com/<你们的帐号>/<仓库名>.git
git push -u origin main
```

每位队员第一次提交前，先在这个资料夹设好自己的名字和邮箱：

```bash
git config user.name "你的名字"
git config user.email "你的邮箱"
```
